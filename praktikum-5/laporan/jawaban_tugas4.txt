TUGAS 4. REFLEKSI KONSEP ENKAPSULASI

1. Mengapa private saja belum cukup untuk memastikan object valid?
• Private hanya menutup akses langsung dari luar class.
• Jika setter menerima nilai apa pun, nilai salah tetap masuk lewat setter.
• Contoh: setSemester() tanpa pemeriksaan menerima -7. Hasilnya sama seperti property public.
• Object valid butuh tiga hal: property private, validasi di constructor dan setter, serta antarmuka yang jelas.

2. Kapan setter tidak perlu dibuat?
• Setter tidak perlu untuk atribut yang tidak boleh berubah. Contoh: NIM pada class Mahasiswa. Tidak ada setNim().
• Setter tidak perlu untuk nilai yang berubah lewat aturan tertentu. Contoh: saldo pada class Rekening. Saldo berubah lewat setor() dan tarik(), tidak lewat setSaldo().

3. Mengapa tambahStok() dan kurangiStok() lebih aman daripada setStok() bebas?
• Setiap method punya aturan sendiri. tambahStok() menolak jumlah nol atau negatif. kurangiStok() menolak jumlah yang melebihi stok.
• Nama method menjelaskan maksud perubahan. setStok(0) tidak menjelaskan apakah buku terjual atau data dihapus.
• Pemakai class tidak bisa menimpa stok dengan angka sembarang.
• Aturan bisnis ada di satu tempat, yaitu di dalam class Buku.

4. Apakah __get() dan __set() wajib untuk menerapkan enkapsulasi?
• Tidak wajib. Enkapsulasi cukup dengan property private, getter, setter, dan method perilaku.
• __get() dan __set() justru bisa melemahkan enkapsulasi. Jika __set() menyimpan nilai ke property mana pun tanpa validasi, hasilnya sama dengan property public.
• Proyek ini tidak memakai __get() dan __set(). Getter dan method eksplisit lebih mudah dibaca dan diuji.

5. Bagaimana perubahan public menjadi private memengaruhi DataMahasiswa.php dan index.php?
• DataMahasiswa.php: $m->nim diganti $m->getNim() pada constructor dan tambah(). Method cari() tidak berubah karena memakai NIM sebagai key array.
• index.php, bagian tabel: $m->nama dan $m->semester diganti $m->getNama() dan $m->getSemester(). Semua kolom lain memakai getter yang sesuai.
• index.php, form Edit: nilai form diisi dari getter. NIM tampil readonly dan dikirim lewat field nim_lama.
• index.php, proses ubah: aplikasi mengambil object lama lewat $repo->cari(), lalu memanggil ubahProfil(). Aplikasi tidak menulis property langsung.
• index.php, input salah: try dan catch menangkap InvalidArgumentException, lalu pesan ditampilkan ke pengguna.
